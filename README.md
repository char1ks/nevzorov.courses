# nevzorov.courses
DB Lecture Materials for nevzorov.courses

## Обзор стендов

Этот репозиторий содержит 5 практических стендов для изучения работы с базами данных:

### 1. **01-index-speedup-pg** — Ускорение запросов с индексами PostgreSQL
Демонстрация того, как индексы ускоряют поиск данных в PostgreSQL.

**Что делает:**
- Создаёт таблицу с 1 миллионом записей
- Замеряет время поиска случайных значений БЕЗ индекса
- Создаёт индекс на поле value
- Замеряет время поиска С индексом
- Сравнивает результаты

**Запуск:**
```bash
cd 01-index-speedup-pg
./run.sh
```

**Требования:**
- Docker
- Python 3
- pip

---

### 2. **02-index-slowdown-pg** — Замедление при избыточных индексах PostgreSQL
Демонстрация негативного влияния избыточных индексов на производительность INSERT-операций.

**Что делает:**
- Создаёт таблицу с несколькими индексами
- Замеряет время вставки данных с индексами
- Удаляет индексы
- Замеряет время вставки без индексов
- Сравнивает результаты

**Запуск:**
```bash
cd 02-index-slowdown-pg
./run.sh
```

**Требования:**
- Docker
- Python 3
- pip

---

```bash
./run.sh
```

**Требования:**

### 4. **04-write-through-cache-redis** — Кэширование Write-Through с Redis
Демонстрация паттерна кэширования Write-Through с использованием Redis и PostgreSQL.

**Что делает:**
- Настраивает PostgreSQL и Redis
- Реализует паттерн Write-Through (запись одновременно в БД и кэш)
- Демонстрирует ускорение чтения из кэша

**Запуск:**
```bash
cd 04-write-through-cache-redis

```

**Требования:**
- Docker
- Python 3
- pip

---

### 5. **05-replication-pg** — Репликация PostgreSQL
Демонстрация мастер-слейв репликации в PostgreSQL.

**Что делает:**
- Настраивает master-узел PostgreSQL
- Настраивает slave-узел с репликацией
- Демонстрирует асинхронную репликацию данных
- Показывает состояние репликации

**Запуск:**
```bash
cd 05-replication-pg
docker compose up -d
```

**Подключение:**
- Master: `localhost:5432`
- Slave: `localhost:5433`

**Требования:**
- Docker

## Общие требования для всех стендов

- **Docker** — для запуска контейнеров с базами данных
- **Python 3.7+** — для запуска скриптов (кроме 05-replication-pg)
- **pip** — для установки зависимостей Python

## Запуск конкретного стенда

Каждый стенд имеет свой `run.sh` скрипт, который:
1. Устанавливает Python-зависимости
2. Запускает Docker-контейнеры
3. Ждёт готовности сервисов (healthcheck)
4. Выполняет демонстрационный скрипт
5. Останавливает контейнеры

Просто перейдите в папку стенда и выполните:
```bash
./run.sh
```

## Остановка

Если вы запустили стенд вручную без `run.sh`, остановите контейнеры:
```bash
cd <папка-стенда>
docker compose down
```

Для полного удаления данных (включая volumes):
```bash
docker compose down -v
```
